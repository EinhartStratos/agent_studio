# Agent Studio 项目设计问题与重构建议

> 审查日期：2026-08-06  
> 审查对象：当前工作区代码，不含对 `third_party` 上游项目本身的全面评价  
> 目标：找出真实设计风险，并给出可分阶段执行、可验收的重构路线

## 1. 审查结论

项目已经从“远程网页壳”演进成“Vue 原生桌面 Agent”，但旧架构没有退出，形成了两套产品形态、两套 Agent 驱动和多套状态存储并存的局面。当前最紧急的问题不是代码风格，而是安全边界：任意远程/热更新页面与原生页面共享高权限 Preload，ACP 工具权限自动放行，模型凭证还可能进入配置、渲染进程和日志。

建议在继续添加团队空间、市场等功能前，先完成 P0 安全收口，再统一 Agent Service、会话存储和生命周期；否则功能越多，后续迁移成本越高。

### 已验证基线

- `npx tsc --noEmit`：通过。
- `npm run build`：通过。
- Renderer 构建结果：JS 约 3.11 MB，CSS 约 472 KB，存在明显的首屏体积优化空间。
- 根项目没有 `test`、`lint`、`format`、`typecheck` 脚本，也没有根项目测试文件。
- Markdown 过滤逻辑已用 `javascript:` 链接复现绕过，属于已验证问题，不是理论推测。
- 审查前已有 `resources/config/app-config.json` 的用户未提交修改；本文未改动该文件。

## 2. 当前真实架构

```text
Vue Renderer
    │ window.electronAPI（同一套高权限 API）
    ▼
Preload / contextBridge
    │ 约 40 个 invoke/event 接口
    ▼
Electron Main
    ├── legacy Agent JSON-RPC
    ├── native IPC
    ├── PiSdkDriver
    │   ├── AcpDriverBridge（默认）
    │   └── SessionSupervisor（SDK）
    ├── Config / Marketplace / Update
    └── 文件系统、进程、剪贴板、窗口能力
```

当前默认链路是 `Renderer → native IPC → PiSdkDriver → AcpDriverBridge → pi-acp → Pi 二进制`。SDK 和 legacy 链路仍然编译、注册并暴露。

## 3. 优先级定义

- **P0**：存在凭证泄露、本地代码执行、供应链或权限绕过风险；修复前不建议发布。
- **P1**：会造成数据不一致、更新失败、资源泄漏、维护失控或明显性能问题；应作为下一阶段主线。
- **P2**：影响产品可信度、开发效率、包体、可访问性或文档质量；在边界稳定后处理。

## 4. P0：必须先修复

### P0-1 远程内容与本地权限没有隔离

**证据**

- 全局关闭 Chromium 沙箱：`src/main/index.ts:14-17`。
- 主窗口 `sandbox: false`：`src/main/window.ts:25-40`。
- `url`、热更新、本地文件和原生 UI 共用同一窗口与 Preload：`src/main/window.ts:42-69`。
- Preload 向所有页面暴露配置、进程、文件、更新、会话等完整能力：`src/preload/index.ts:6-114`。
- 没有发现 `will-navigate`、`setWindowOpenHandler`、权限请求处理或 CSP。

**影响**

远程站点、被篡改的内容包、被导航后的页面或 Renderer XSS 都能直接调用本地能力。`contextIsolation: true` 和 `nodeIntegration: false` 无法弥补“桥本身权限过大”。

**重构方向**

1. 原生 UI 使用独立、沙箱化窗口，只加载受信任的应用资源。
2. 远程/热更新内容使用独立 Session/窗口，默认不注入 Preload；确需能力时提供单独的最小只读桥。
3. 每个 IPC 处理器校验 `event.senderFrame.url`、窗口身份和能力令牌，不能只相信通道名。
4. 禁止主窗口任意导航；外链交给系统浏览器，并配置严格 CSP。

### P0-2 `shell:execute` 白名单等同于任意代码执行

**证据**

`src/main/security.ts:4-43` 允许 `python`、`node`、`pi`、`git`，参数不校验，也没有固定 cwd、超时、输出上限和调用方校验。

**影响**

只要页面能调用 Preload，就能用 `node -e`、`python -c` 等执行任意代码；无限输出还可能耗尽主进程内存。审计日志会原样记录参数，可能再次泄露敏感值。

**重构方向**

删除通用命令执行 API。把业务需要改成明确命令对象，例如 `gitStatus(workspaceId)`；在主进程内部生成参数，设置目录边界、超时、输出上限和取消机制。

### P0-3 模型凭证生命周期不安全且语义错误

**证据**

- 配置类型允许明文 `apiKey`：`src/shared/config.ts:18-29`。
- `config:get` 返回完整配置：`src/main/config.ts:544-566`、`src/preload/index.ts:34-40`。
- 默认值把 `apiKeyEnv` 写成环境变量名：`src/main/config.ts:20-27`；实现却仅在值以 `$` 开头时读取环境变量，否则把变量名本身当密钥：`src/main/pi-sdk-driver/runtime-deps.ts:64-77`。
- 运行时把完整 `auth.json` 内容写入持久日志：`src/main/pi-sdk-driver/runtime-deps.ts:183-214`。
- 当前工作树 `resources/config/app-config.json:18-24` 的凭证字段存在疑似明文值，本文不记录其内容。
- 每次同步都会整体覆盖 Pi 的 `auth.json` 和 `models.json`，可能抹掉登录态或用户配置：`src/main/pi-sdk-driver/runtime-deps.ts:130-218`。

**立即动作**

1. 立即吊销并轮换当前疑似泄露凭证，不要把原值复制到 Issue、提交信息或日志。
2. 停止记录 `auth.json`、Prompt、工具输入中的敏感字段，并清理已有调试日志。
3. Renderer 只读取脱敏后的 `PublicAppConfig`；密钥只在 Main 中通过环境变量或系统安全存储解析。
4. 明确定义 `apiKeyEnv: "OPENAI_API_KEY"` 的语义，不允许它兼任明文值。
5. 不再整体覆写 Pi 配置文件；为应用托管配置建立独立命名空间和合并策略。

### P0-4 ACP 权限与项目信任被自动放行

**证据**

- ACP 权限请求自动选择 `allow_once`：`src/main/pi-sdk-driver/acp-driver-bridge.ts:252-269`。
- SDK 加载项目资源时无条件返回信任：`src/main/pi-sdk-driver/session-supervisor.ts:174-181,249-256`。
- 前端的 `currentPermission` 只保存 UI 状态，没有传给后端：`src/renderer/src/stores/session.ts:116-121,282-290`。

**影响**

界面显示的“只读/权限”与真实执行策略无关，用户会产生错误安全预期；恶意项目 Skill 或 Agent 工具可能在没有确认的情况下读写文件、执行命令。

**重构方向**

建立 Main 进程 `PermissionService`：按工作区持久化信任，按工具类型计算策略，把审批请求发送给原生 UI，并支持拒绝、单次允许和工作区允许。未实现审批前应默认拒绝，而不是自动允许。

### P0-5 AI Markdown 可触发 XSS，并可升级为本地权限滥用

**证据**

- `marked` 输出仅用正则删除部分标签/属性：`src/renderer/src/components/ChatView.vue:183-191`。
- 结果通过 `v-html` 注入：`src/renderer/src/components/ChatView.vue:235-239,291`。
- 实测 `javascript:` URL 会保留；无 CSP 与导航限制会扩大影响。

**重构方向**

使用经过维护的 HTML Sanitizer 严格白名单，禁止原始 HTML或至少禁止脚本协议、SVG/MathML 和危险 URL；链接统一拦截。增加恶意 Markdown 回归测试和 CSP。静态演示页的 `v-html`（`ProjectDetailView.vue:19-23,80`）也应改为结构化文本。

### P0-6 Agent 更新入口允许 Renderer 提交任意下载参数

**证据**

- Renderer 直接提交 `{version,url,hash}`：`src/preload/index.ts:21-24`。
- IPC 不校验来源，也不与服务端检查结果绑定：`src/main/agent-update.ts:277-287`。
- 支持 HTTP，hash 可省略：`src/main/agent-update.ts:104-129,214-236`。
- 下载内容进入优先执行的 `userData/agent-bin`。

**影响**

获得 Renderer 执行能力的攻击者可以投放未校验的 Agent 可执行文件；legacy 模式可立即运行，ACP 模式最迟会在后续启动运行。

**重构方向**

Renderer 只能提交服务端签发的更新 ID；Main 自己重新拉取并校验清单。强制 HTTPS、签名和 SHA-256，校验版本/URL/归档路径，限制下载与解压体积，并在隔离目录完成验证后原子切换。

## 7. 建议目标架构

```text
Trusted Renderer（仅本地 app 页面，sandbox）
        │ typed + runtime-validated IPC
        ▼
IPC Router
  - SenderPolicy / Schema / RateLimit / Error DTO
        ▼
DesktopAgentService
  - SessionSnapshot / Capability / Permission / Lifecycle
        │
        ├── AcpAgentDriver
        └── SdkAgentDriver（若确有保留价值）
        │
        ├── SessionRepository（唯一权威存储）
        ├── ConfigRepository + SecretStore
        ├── WorkspacePathPolicy
        └── TransactionalUpdateService

Remote Content Window（独立 Session，无通用 Preload）
```

核心原则：Renderer 不知道 Pi/ACP 私有对象；Driver 不直接操作 UI；配置、密钥、会话和更新各自只有一个所有者；所有外部输入在进入业务层前完成来源校验与 Schema 校验。

## 8. 推荐实施顺序

### 阶段 A：安全止血

1. 轮换已暴露凭证，删除密钥日志，拆分公开配置与私密配置。
2. 禁用远程页面的通用 Preload；恢复沙箱，加入导航、权限和 CSP 策略。
3. 移除 `shell:execute`，修复 Markdown Sanitization。
4. 更新安装改为 Main 内部可信清单、强制校验、staging 与原子回滚。
5. 把 ACP 权限改为默认拒绝，并接入真实审批 UI。

### 阶段 B：建立稳定边界

1. 定义 `AgentDriver`、`DriverCapabilities`、`AgentSessionSnapshot` 和统一事件类型。
2. 建立 `DesktopAgentService`，IPC 只调用 Service，不直接调用驱动或文件系统。
3. 拆分 `AcpDriverBridge`，禁止业务代码访问 `pi-acp` 私有字段；无法避免的访问集中在一个兼容适配器。
4. 统一初始化、重启、更新、关闭生命周期，并增加 single-flight。
5. 选择会话权威存储，补迁移和一致性修复工具。

### 阶段 C：可靠性与性能

1. 文件树懒加载，文件预览流式限长，Main 中移除高频同步 I/O。
2. Transcript 使用 revision + snapshot/compaction；Renderer 用 reducer 增量更新。
3. 配置和索引改为原子写；会话删除、更新安装使用事务语义。
4. 固定 Node/Bun/npm 与 Pi 兼容版本，CI 改 matrix，核心构建失败即停止发布。

### 阶段 D：产品收口

1. 删除或隔离演示页面、旧标题栏、legacy API 和未实现入口。
2. 拆分前端 Store，统一产品名称、版本、主题和错误展示。
3. 更新 README 与 ADR，补可访问性和包体预算。

## 9. 最低验收标准

- 远程页面、导航后的页面和热更新内容无法访问高权限 `electronAPI`。
- 恶意 Markdown（脚本协议、事件属性、SVG 等）不能执行，外链不会在高权限窗口内导航。
- Renderer 无法读取 API Key；日志中搜索不到凭证；`apiKeyEnv` 能正确解析环境变量。
- 工具读写/执行前会按真实权限策略审批，“只读”模式可由自动化测试证明不会写文件或执行命令。
- 更新包无签名/hash、版本非法、解压越界、探活失败时全部拒绝或自动回滚；ACP 确认运行的是新版本。
- 并发初始化只创建一个 Driver；退出后 Pi 子进程、监听器和 SQLite 全部释放。
- 删除会话后重启和重新扫描都不会复活；长会话回放时间和磁盘体积有上限。
- CI 至少执行 typecheck、lint、单元测试、安全边界集成测试、构建和更新回滚测试。

## 10. 当前值得保留的设计

- 主进程、Preload、Renderer 已有基础分层，`contextIsolation` 和关闭 Node Integration 的方向正确。
- TypeScript strict 已开启，当前类型检查和生产构建通过。
- IPC 写配置时已有字段校验，内容更新已有 SHA-256 校验雏形。
- Agent 更新已经考虑备份，ACP Transcript 已考虑顺序、缓存和磁盘恢复。
- SDK 路径已有工作区边界检查雏形，事件订阅也保留取消函数。

这些基础可以复用，但必须把“已有机制”升级成真正覆盖所有驱动、所有窗口和所有输入来源的统一策略，而不是继续在现有大类中追加分支。
