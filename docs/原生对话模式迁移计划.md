# 原生对话模式迁移计划

## 一、目标

将 `agent_studio` 从“内嵌网页 Shell”升级为“纯原生 Electron 桌面应用”，直接以原生 UI 承载 Pi 的多轮对话能力。首期只完成普通对话的全流程，不引入 Skill 配置、扩展、Worktree、设置页等复杂模块。

**核心要求：**
- 不内嵌网页，主界面使用原生 Electron 渲染进程 UI。
- 支持多会话管理（创建、打开、切换、删除、重命名）。
- 支持普通对话流：发送消息、接收流式 AI 回复、取消运行。
- 支持默认工具调用展示与结果渲染。
- 支持文件预览、Diff 查看。
- 引入 `PiSdkDriver`，统一封装与 Pi 的交互。
- 配置文件增加“模型配置组”，但先不在 UI 中配置模型，也不需要设置页。
- 配置中 `homepage.type` 新增 `native` 模式，原有 `default` / `url` / `file` 模式保持不变。
- **Skill 配置、扩展、Worktree 本期不做。**
- **代码实现不引用 `ref/pi-gui-main/` 中的文件**，该目录仅作为设计参考，后续会删除。

---

## 二、当前项目现状

目前 `agent_studio` 是一个 Electron Shell：

- 主进程通过 `pi --mode rpc` 子进程与 Pi 进行 JSON-RPC 通信。
- 渲染进程通过 `window.electronAPI` 调用 IPC 接口：
  - `invokeAgent` / `agent:message`：执行 Agent 命令与事件通知。
  - `executeCommand`：本地白名单命令执行。
  - `getAppConfig` / `setAppConfig` / `updateAppConfig`：配置读写。
  - `getAgentStatus` / `restartAgent`：Agent 状态与重启。
- 配置以 `resources/config/app-config.json` 为默认，支持用户数据目录覆盖。
- 当前渲染进程页面 `src/renderer/src/main.ts` 只是简单调试页，没有真正的会话 UI。
- 用户已确认使用 **React + TypeScript + TailwindCSS（可引入 shadcn/ui）** 构建原生 UI。

## 三、目标架构

```
Renderer (原生 UI：会话列表、对话时间线、Composer、Diff/文件预览)
    │
    ▼
Preload (contextBridge 暴露 IPC 接口)
    │
    ▼
Main Process
    ├── Window / App 生命周期
    ├── IPC Router (统一转发到 PiSdkDriver)
    ├── PiSdkDriver (封装 Pi 会话与运行时交互)
    │       ├── SessionSupervisor (会话创建/打开/发送/取消/归档/分叉/树导航)
    │       └── RuntimeSupervisor (模型/认证/运行时资源)
    └── Config / Agent 启动与状态管理
```

说明：
- `PiSdkDriver` 是 GUI 与 Pi 核心之间的唯一入口。
- `SessionSupervisor` 负责会话生命周期。
- `RuntimeSupervisor` 负责认证、模型注册表、运行时设置。
- 渲染进程不再依赖外部网页，所有 UI 组件内置在 `src/renderer/`。
- 会话 `.jsonl` 文件同时保存在 `userData/sessions/` 和用户指定的 workspace 目录，并在 SQLite 中建立索引表，便于后续搜索。


说明：
- 配置中直接定义多个模型别名与参数。
- 当前不暴露 UI，用户通过编辑配置文件切换模型。

## 五、明确不做的范围

以下内容本期不实现：

1. **Skill 配置与加载**：不读取、不展示、不禁用/启用 Skill。
2. **扩展（Extensions）**：不加载、不绑定扩展，不处理扩展命令。
3. **Worktree 管理**：不实现 Git Worktree 的创建、切换、删除。
4. **设置页（Settings View）**：不在 UI 中提供模型、提供商、技能、扩展的设置界面。
5. **主题皮肤切换**：优先使用默认主题，不实现多套主题预设。
6. **终端集成**：不集成 node-pty 终端面板。
7. **子会话编排（Orchestration）**：不实现 Agent 的子任务编排。
8. **通知系统**：不实现桌面通知/权限管理。

## 六、实施建议顺序

1. **配置层**：扩展 `src/shared/config.ts`、`resources/config/app-config.json`、`src/main/config.ts`，支持 `native` 首页类型与模型配置组。
2. **安装依赖**：安装 `@earendil-works/pi-coding-agent`、`react`、`react-dom`、`tailwindcss`、`better-sqlite3` 等。
3. **主进程骨架**：创建 `src/main/pi-sdk-driver/` 目录，实现 `PiSdkDriver` 基础类、`SessionSupervisor`、`RuntimeSupervisor`、`RuntimeDeps`。
4. **会话生命周期**：实现会话创建、打开、列出、发送消息、取消运行，并持久化 `.jsonl` 会话文件到 `userData/sessions/` 与 workspace 目录。
5. **SQLite 索引**：建立会话元数据表，支持双路径映射。
6. **事件与 IPC**：打通主进程 → Preload → 渲染进程的事件通道（流式消息、状态变化）。
7. **状态页验证**：先写一个最小状态页，调用 `PiSdkDriver` 各接口并显示连通状态。
8. **渲染进程 UI**：搭建 React + Tailwind 骨架，实现 Sidebar、Timeline、Composer。
9. **工具调用 / 文件预览 / Diff**：在 Timeline 中渲染工具调用，增加 WorkspaceTree / FilePreview / DiffPanel。
10. **打磨与测试**：跑通完整对话流程，验证配置读取、模型切换、文件预览、Diff 查看。

## 七、已确认事项

以下为用户已确认的关键决策，作为后续开发依据：

1. **UI 框架**：使用 React + TypeScript，允许引入 TailwindCSS 与 shadcn/ui。
2. **工作区/会话存储路径**：会话 `.jsonl` 同时保存到 `userData/sessions/` 和 workspace 目录；使用 SQLite 建表管理会话元数据，方便后续查询与搜索。
3. **模型配置格式**：采用文档中示例的模型配置组格式，当前先支持 `provider` / `modelId` / `apiKeyEnv` / `baseUrl` / `enabled` 等字段。
4. **Diff 查看范围**：纯文本 diff，并提供目录树让用户选择要预览的文件。
5. **文件预览范围**：以文本文件预览为主，目录树选择文件。
6. **Pi 核心依赖**：按推荐方式使用 npm 包 `@earendil-works/pi-coding-agent`；原二进制构建流程不变，原生模式直接通过 npm 包调用。
7. **开发顺序**：先实现主进程 + `PiSdkDriver`，再写一个状态页验证各接口连通，最后补全原生 UI。
8. **首页兼容**：`homepage.type` 新增 `native` 模式，原有 `default` / `url` / `file` 模式保持不变、不损坏。
